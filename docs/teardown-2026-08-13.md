# Red Team Teardown — prediction-market-builder

Date: 2026-08-13
Method: five hostile review agents across backend core, security, AI/agentic stack, frontend+infra, and repo hygiene/tests. Every finding verified against source with file:line.

## Executive verdict

**This project must not run in production as-is, and it cannot even build/deploy as-is.** The security posture is disqualifying on its own (forgeable JWTs, in-process `exec` of LLM output, unauthenticated WebSockets, arbitrary file read, pervasive IDORs). Beneath that, large fractions of the product are theater: the risk engine is a no-op, the AI tool-calling loop cannot work as written, the "research" engine iterates on simulated noise, paper-trading PnL is mathematically always positive, the compose file cannot build, monitoring cannot alert, and a third of the test suite is ceremonial.

Git state: **zero commits**. Everything is untracked; the first `git add .` will permanently commit junk (DBs with PII, logs, backups, build artifacts) unless cleaned first.

## Recommended target architecture (from teardown)

1. **Flatten** the repo: promote `prediction-market-builder\{backend,frontend,infrastructure,docs}` to root; delete wrapper + junk.
2. **Cut dead/unsafe AI sprawl**: delete `skill_creator` (RCE), `agent_spawner` (untooled, uncancellable), `ga_optimizer`/`mc_sensitivity` (test-only), duplicate NSGA-II/TabPFN, lance/duckdb managers (no prod callers), RLM DSPy layer, fake `/features` endpoint. Keep: one search pipeline (SSRF-guarded), one vector store, one schema-validated tool dispatch with human confirm, one research loop honestly labeled.
3. **One source of truth per concern**: alembic only (drop `create_all`), single DI container for services, single typed API client on frontend, one `.env.example` with every var, one docs home.
4. **Security baseline**: fail-fast secret key, proper KDF, encrypted exchange keys at rest, ownership checks on every route, auth'd WS, sandboxed exec or none, rate limits scoped per-user, internal-only infra ports.
5. **Money correctness**: real PnL accounting, atomic ledger ops with idempotency, risk engine actually wired to its node handlers, no mock markets without explicit `source: "mock"`.
6. **Infra that can actually run**: compose at root with real contexts, prod frontend build, real postgres wiring (or honest sqlite+volume), mounted alert rules + registered middleware, pinned images, secrets via env, healthchecks.
7. **Tests that bite**: delete the ceremonial files, fix the security suite to assert the *fixed* behavior, add cross-tenant test matrix, contract tests against real payload shapes, `tsc --noEmit` in CI.
